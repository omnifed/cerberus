# The Docs Site

The docs at `docs/` are the official Cerberus website and the dev sandbox. It is a
Next.js app with MDX content compiled by [Velite](https://velite.js.org/).

- This version of Next.js has breaking changes. Read `docs/AGENTS.md` before
  changing app code.
- For code conventions, see the [style guide](./style-guide.md).
- To add a component page, see [create-doc-component-page](./create-doc-component-page.md).

Run it with `pnpm start:docs` from the repo root.

## Structure

| Path                         | What                                                                                                  |
| ---------------------------- | ----------------------------------------------------------------------------------------------------- |
| `content/docs/<section>/`    | Docs pages (MDX). Sections: `get-started`, `components`, `data-grid`, `signals`, `styling`, `theming` |
| `content/blog/`              | Release blog posts (MDX)                                                                              |
| `examples/<section>/<name>/` | Demos: `*.demo.tsx` files registered in `index.tsx`                                                   |
| `generated/api-specs/`       | Component API specs. **Generated by `pnpm generate:docs`, don't edit**                                |
| `app/docs/[[...slug]]/`      | The route that renders every docs page                                                                |
| `app/docs/docs.config.ts`    | The top-level nav sections                                                                            |
| `app/blog/`                  | The blog index and post routes                                                                        |
| `app/(llms)/`                | The `llms.txt` routes                                                                                 |
| `components/`                | Site UI and the MDX components (`shared-mdx.tsx` lists them)                                          |
| `lib/`                       | Content loaders (`docs-content.ts`, `blog-content.ts`) and helpers                                    |
| `system/`, `panda.config.ts` | The site's Panda config and global CSS                                                                |
| `velite.config.ts`           | The frontmatter schemas for docs pages and blog posts                                                 |

## How pages are built

Velite compiles every MDX file in `content/` using the schemas in
`velite.config.ts`. A docs page's folder is its section and its file name is its
slug, so `content/docs/components/accordion.mdx` is served at
`/docs/components/accordion` and shows up in the nav under its `group`. There is
no route or nav list to update.

## MDX components

These are available in every page and post without an import:

| Component                                                             | Use                                         |
| --------------------------------------------------------------------- | ------------------------------------------- |
| `<Example path demo />`                                               | Renders a demo with its source code         |
| `<ComponentApi spec />`                                               | Renders a component's generated API table   |
| `<FeatureBadge since />`                                              | Marks a heading as new in a version         |
| `<NoteAdmonition description />`, `<WarningAdmonition description />` | Callouts                                    |
| `<BashTabs code />`                                                   | A command with pnpm, Deno, Bun and npm tabs |

## Blog posts

Release posts live in `content/blog/` (e.g. `v1-8-release.mdx`, `v2-release.mdx`). The
frontmatter needs `slug`, `date`, `author`, `title`, `description`, `category`,
`version` (quoted, e.g. `'2.0'`), `timeToRead` and `tag`. The blog index lists
posts by `version`, newest first.
